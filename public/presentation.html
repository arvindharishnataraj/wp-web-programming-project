Slide 02 • Motivation & Problem Formulation

Executive Abstract & Problem Statement

The Challenge

  • Earthquake, cyclone, and atmospheric telemetry are scattered across isolated, uncoordinated databases.
  • Most existing weather applications refresh once every 6 to 12 hours, missing rapid micro-climate shifts.
  • South Indian coastlines are vulnerable to sudden Bay of Bengal cyclonic depressions and Indian Ocean tsunamis.

The Proposed Solution

  • GeoPulse 360: A unified, high-performance single-page mission control dashboard.
  • Aggregates live USGS seismic telemetry, Open-Meteo weather & AQI, and ISS orbital data.
  • Zero subscription fees or proprietary API keys required.
  • Sub-5ms local proxy caching to prevent rate-limiting and maximize throughput.

Core Web Innovations

  • Server-Sent Events (SSE): Continuous push streaming over persistent HTTP connections.
  • Interactive Leaflet GIS: Concentric seismic wave markers scaled logarithmically by Richter magnitude.
  • Web Audio API: In-browser synthetic tactical sonar and emergency alert sirens.
  • Dual Persistence: Browser LocalStorage + Server JSON file storage.

Slide 05 • Full-Stack Software Engineering

System Architecture & Data Pipeline

Backend Core (Node.js & Express)

  • REST Proxy Architecture: Eliminates CORS cross-origin restrictions and encapsulates API logic.
  • Intelligent In-Memory Caching:
    • USGS Earthquakes: 25-second TTL
    • Weather & AQI: 3-minute TTL
    • ISS Telemetry: 2-second TTL
  • Server-Sent Events (SSE): Persistent endpoint /api/events/live streaming continuous heartbeat telemetry packets.
  • JSON Database: CRUD persistence stored in data/bookmarks.json.

Frontend Engine (Modular ES6+)

  • Single Page Architecture: Pure vanilla ES6+ with zero heavy framework overhead for maximum speed.
  • map.js: Leaflet.js geospatial engine, custom SVG DivIcons with pulsing CSS animations.
  • charts.js: Chart.js visualizations with dynamic dark/light theme re-rendering.
  • weather.js: Geocoding search debouncer, WMO code translator, and AQI gauge rating.
  • audio.js: Web Audio API acoustic synthesizer generating tactical frequencies.

Slide 08 • Browser Acoustic Synthesis

Synthetic Acoustic Warning System (Web Audio API)

Why Synthesized Audio?

  • Conventional web apps load external MP3/WAV files, causing network latency, autoplay blocks, and bandwidth waste.
  • GeoPulse 360 uses browser-native AudioContext, OscillatorNode, and GainNode.
  • Zero audio file downloads — 100% generated in real time via mathematical wave functions.
  • Sub-millisecond acoustic response time.

Acoustic Sound Profiles

  • Tactical Sonar Ping: Sine wave sweeping from 1046.5 Hz (C6) down to 523.25 Hz with exponential decay (plays on refresh).
  • Critical Hazard Siren: Dual-tone sawtooth wave (440 Hz & 880 Hz) modulating rapidly to signal major earthquakes (M >= 5.0).
  • Tactile Click: Crisp 800 Hz to 400 Hz 40ms pulse for button feedback.
Slide 09 • API Reference & Protocol

Backend RESTful API Specifications

Telemetry Endpoints

  • GET /api/health: System health, uptime seconds, and timestamp.
  • GET /api/earthquakes?minMag=X&limit=Y: Cached USGS feed with aggregate stats.
  • GET /api/weather?lat=X&lon=Y: Parallel meteorological & AQI lookup.
  • GET /api/geocode?q=Query: Debounced global city autocomplete.
  • GET /api/iss: Live orbital coordinates and speed.
  • GET /api/stats: High-level KPI summaries for dashboard cards.

Streaming & Export Endpoints

  • GET /api/events/live: Server-Sent Events (SSE) persistent stream pushing telemetry heartbeats every 6 seconds.
  • GET /api/bookmarks: Lists all saved user observation stations.
  • POST /api/bookmarks: Saves new custom coordinates to bookmarks.json.
  • DELETE /api/bookmarks/:id: Deletes an observation station.
  • GET /api/export?format=csv: Generates and streams downloadable CSV incident reports.

Slide 11 • Viva-Voce Cheat Sheet

Expected Viva-Voce Questions & Answers

Q1: Why did you choose Server-Sent Events (SSE) instead of WebSockets?
Ans: SSE operates over standard HTTP, has native browser reconnection, works through corporate proxies, and is much lighter for unidirectional server-to-client telemetry pushing without the full-duplex overhead of WebSockets.
Q2: How do you prevent API rate limits from third-party services?
Ans: We built an in-memory TTL cache inside server.js. USGS earthquakes are cached for 25s, weather for 3 minutes, and ISS for 2s. Repeated hits resolve in <5ms without re-querying external servers.
Q3: How is data persisted across browser sessions?
Ans: Dual persistence: User UI preferences (theme, audio, intervals) are stored in browser LocalStorage, while observation stations are synchronized to the backend data/bookmarks.json database.
Q4: Why is this project significant for South India?
Ans: It provides dedicated observatories for Chennai (cyclone radar), Bengaluru (ISRO hub), Hyderabad (INCOIS tsunami center), Kochi (monsoon onset), Vizag, and the Andaman subduction trench fault line.
